# LG Subscribe MiniApp preview

Open **home.html** to explore the complete demo. **products.html**, **product.html**, **checkout.html**, and **consultation.html** open directly at the catalog, dishwasher detail, purchase form, and separate consultation form. **subscribe.html** remains a compatible entry into the purchase form. Each HTML file includes its fonts, images, styles, scripts, and catalog, so it works without a server or internet connection.

The design uses Montserrat and [LG’s official palette](https://www.lg.com/global/our-identity/color/): Active Red `#FD312E`, Heritage Red `#A50034`, Warm Grey `#F0ECE4`, white, and black. The showroom direction uses larger campaign typography and appliance stages, flat warm surfaces, a charcoal kitchen promotion, and clearer product prices. The home page leads with manually controlled campaign banners. A searchable catalog and a bottom-sheet picker give access to all 13 product types, followed by contextual filters. Product cards and the detail dock use **Mua** for the three-step purchase flow: buyer information, delivery/installation, and order review.

Consultation appears in a separate service section outside product cards. It collects name, phone, and email and automatically attaches the selected catalog model. General consultation entry points require selecting a product/model first. The alternative **Gọi 1800 1503** action uses `tel:18001503`. Consultation requests can be reviewed from **Tài khoản → Yêu cầu tư vấn**.

The catalog contains 88 customer products across 13 product types. LG category IDs and labels come from **Product level**, columns **I:N**, in the supplied workbook: file levels 2, 3, and 4 become canonical levels 1, 2, and 3. Prices and contract totals come from **Total MiniApp**. Seven AC component pairs appear as seven customer products while retaining both component paths. Full source rows and mappings are in **taxonomy-mapping.json**.

Four products have unresolved `#N/A` category lookups in the workbook: MD16GQSE0, MD19GQGE0, DVHP50M, and STAGE301. Their mappings remain unresolved and purchasing follows the source’s availability notes. Customers can still request advice about these models. The source workbook was read using its saved formula results and was not modified.

Some product photographs represent a product family; these are labeled as illustrations. Missing measurements stay blank. Campaign copy is a design concept. Purchasing is a local simulation: buyer contact information stays in page memory, while saved items, carts, and sample order references stay on the device. Consultation requests include contact information and the canonical model and are saved on the device under `lgs-consultations-v1`. Without an API endpoint, the confirmation explicitly describes a demo record. No payment, contract, delivery booking, or actual staff notification is performed.

Phone layouts were checked at 320, 390, and 430 pixels. Search, filtering, sorting, plan totals, favorites, cart, form validation, confirmation, and unavailable-product handling were checked in the browser.

Editable sources are **miniapp.css**, **flow.css**, **consultation.css**, **miniapp.js**, and **catalog-full.js**. The visual refinement used the local **ui-ux-pro-max** skill, with LG colors and Montserrat taking precedence over generic palette/font suggestions. Run `python3 preview/build-preview.py` from the project folder to regenerate the six HTML files from the supplied local assets.

For integration, define `window.LG_CONSULTATION_ENDPOINT` before **miniapp.js** runs. The form sends an HTTPS/relative endpoint a JSON `POST` with `ref`, `productId`, `model`, `name`, normalized `phone`, `email`, `createdAt`, and `status: "submitted"`. The server must validate the fields and model mapping, handle authentication/CORS as needed, and return a successful HTTP status only after accepting the request. The form shows success only after that response; on failure it retains the contact information for retry. A successful save also emits the `lg:consultation-created` browser event with the same payload. No live endpoint has been configured in these preview files.
